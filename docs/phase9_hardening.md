## Item 11 detail: patch/update status

**Current versions (this VM):**
- MariaDB 10.4.32
- PHP 8.2.12
- Apache HTTP Server 2.4.58

**Findings:**
- MariaDB 10.4 reached end-of-life on 18 June 2024. The final release of that branch was 10.4.34; this VM is not even on that final patch. No security fixes will ever be published for 10.4 again.
- PHP 8.2's active support ended 31 December 2024; its security-support window closes entirely on 31 December 2026. Current stable PHP is in the 8.5.x series.
- Apache 2.4.58 is on an actively-maintained branch (current: 2.4.71), but 68 CVEs have been fixed in releases since 2.4.58, including 1 critical (`mod_http2` heap corruption/RCE), 7 important (including Windows UNC-path SSRF that can leak NTLM credentials, and a `mod_proxy` authentication-bypass issue), and a larger number of moderate/low severity issues.

**Decision and justification:**
Given the project timeline, an in-place upgrade of all three components was judged too risky to attempt now: MariaDB major-version upgrades in particular can require schema/data migration steps, and a broken XAMPP stack days before submission would jeopardize the whole project. The decision taken was to document the patch gap precisely (versions, EOL dates, concrete CVEs) and propose a remediation plan, rather than either hiding the gap or attempting a rushed fix.

**Remediation plan (documented, not yet executed):**
1. Snapshot/backup the current VM before any version change (building on the Phase 8 backup procedure, extended to cover the `mysql` system database per that phase's own finding).
2. Upgrade MariaDB to a currently-supported LTS release (e.g. the 11.x or current LTS line) in a cloned/test copy of the VM first.
3. Upgrade PHP to a currently-supported version (8.3+) and re-run the full Phase 3-8 test suite against it before touching the working VM.
4. Upgrade Apache to the latest 2.4.x release, re-test `.htaccess`-based protections (Phase 3's config.php block) since some of the fixed CVEs touch `.htaccess`/`ap_expr` handling.
5. Re-run the Phase 9 evidence checklist (items 1-10) after the upgrade, since account/privilege state can be affected by a MariaDB version change.
